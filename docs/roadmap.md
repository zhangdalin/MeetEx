# MeetEx 路线图

日期: 2026-05-05

## 原则

- 先补齐当前 UI 已经暴露的功能入口，再扩展新的产品界面。
- 每个阶段都应能用真实 LiveKit 房间验证。
- 凭据、会议创建和录制控制应先接入后端服务，再进入产品化阶段。
- 用小型控制器和服务边界承接业务逻辑，避免大规模重写。

## 当前状态

- 阶段 0 已完成，项目结构和范围文档已建立。
- 阶段 1 已开始，`MeetingSession` 已落入 `meetingengine`，会中页已改为通过会话层驱动会议。
- 阶段 1 仍未完成，动态会议创建、加入参数采集、目录服务和后端联调尚未接通。

## 阶段 0: 文档和基线整理

目标: 让项目现状、结构和下一步范围清晰可读。

交付:

- README 项目介绍和结构说明。
- 需求、设计和路线图文档。
- 明确已有能力和未完成功能。
- 为后续移除固定 token、补齐设置持久化等工作建立任务清单。

退出标准:

- 新开发者能快速理解 UI、会议、媒体、资源和第三方依赖位置。
- 下一阶段功能范围达成一致。

## 阶段 1: 真实入会链路

目标: 将固定开发房间改为动态会议创建和加入。

当前已完成的首批客户端收敛工作:

- `MeetingSessionCtx` 和 `MeetingSessionJoinOptions` 已落地。
- `MeetingSession` 已作为单场会议会话控制器接管 `MeetingEngine`。
- `InMeeting` 已不再直接持有 `MeetingEngine`。
- `MeetingRoom` 已支持从外部注入 LiveKit URL 和 token。
- 连接日志已开始执行 token 脱敏。

本阶段仍待完成:

- `JoinMeeting` 收集会议号、显示名和入会选项，并显式构造 `MeetingSessionCtx`。
- `Home::onQuickMeeting()` 不再直接打开默认会中页，而是先完成快速会议目录查询。
- 引入 `MeetingService`，屏蔽开发默认值和后端 HTTP 实现差异。
- 加入失败和 token 失败的用户提示。
- 去掉产品构建对固定 LiveKit token 的依赖。

交付:

- 加入会议请求模型: 会议号、显示名、入会选项。
- 后端 API 适配: 会议校验和 LiveKit token 获取。
- 快速会议 API 适配: 创建房间并获取 token。
- 单场会议会话控制器，统一持有 `MeetingEngine`。
- 会中按钮绑定真实本地媒体状态。
- 加入失败和 token 失败的用户提示。

退出标准:

- 用户可以不重新编译客户端就创建快速会议或加入会议号。
- 摄像头和麦克风入会偏好能生效。
- 产品构建不再依赖编译期固定 LiveKit token。

## 阶段 2: 成员、邀请和聊天

目标: 补齐会中协作能力。

交付:

- 成员面板: 参会者列表、音频/视频/发言状态。
- 邀请面板: 会议号、邀请链接和复制操作。
- 聊天面板: 文本消息发送和接收。
- LiveKit data message 消息序列化。
- 基础发送成功、失败和重试状态。

退出标准:

- 两个客户端在同一房间能看到成员状态并互发文本消息。
- 用户能从会中 UI 复制邀请信息。
- 参会者加入/离开和轨道变化能稳定更新成员状态。

## 阶段 3: 屏幕共享

目标: 支持本地屏幕共享发布和远端共享内容展示。

交付:

- 屏幕或窗口源选择。
- `mediaengine` 中新增屏幕采集源。
- 本地屏幕共享发布和取消发布。
- 本地共享状态提示和停止共享操作。
- 远端屏幕共享轨道识别和优先布局。
- 采集权限失败和发布失败提示。

退出标准:

- 用户可以在 LiveKit 会议中开始和停止共享屏幕。
- 远端客户端能区分屏幕共享和摄像头视频。
- 离开会议时屏幕采集停止，轨道被取消发布。

## 阶段 4: 录制和设置

目标: 完成录制控制和本地偏好。

交付:

- 后端控制 LiveKit Egress 的录制服务适配。
- 会中录制状态: 空闲、开始中、录制中、停止中、失败。
- 录制权限和失败提示。
- 音频、视频、录制和通用设置持久化。
- 设备选择 UI 与媒体层连接。
- 诊断导出入口。

退出标准:

- 录制按钮能反映后端真实录制状态。
- 用户设置在重启应用后仍保留。
- 默认入会设置会应用到加入会议流程。

## 阶段 5: 稳定性、体验和打包

目标: 让客户端达到更可靠的测试版本状态。

交付:

- 重连 UI 和房间状态恢复。
- 所有可见面板的空状态和失败状态。
- 日志脱敏和诊断信息整理。
- 多客户端手工测试清单。
- Windows 打包验证，包括 LiveKit 和 Qt 运行时依赖。
- 用户可见文本翻译整理。

退出标准:

- 常用会议流程能经受多次加入和离开。
- 日志能帮助定位问题且不暴露密钥。
- 打包后的 Windows 应用能在干净测试机器上运行。

## 后续扩展

以下功能有价值，但不属于当前 UI 驱动的 MVP 范围:

- 主持人转移和高级会控。
- 等候室和入会审批。
- 企业通讯录集成。
- 云录制列表和回放门户。
- 白板和共享笔记。
- 会议转写和智能纪要。
- 端到端加密策略 UI。
- 大型会议布局优化。
