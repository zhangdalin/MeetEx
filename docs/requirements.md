# MeetEx 需求文档

日期: 2026-05-05

## 范围

本文档描述 MeetEx 下一阶段功能需求。范围以当前项目中已经存在的 UI 入口为准，不扩展到完整企业会议平台。目标是把现有 LiveKit Windows 客户端从演示雏形补齐为可持续演进的 MVP。

## 目标

- 补齐当前 UI 已经暴露但逻辑尚未完成的会议功能。
- 保持现有 Qt Widgets、`meetingengine`、`mediaengine` 的工程结构。
- 将编译期写死的 LiveKit 房间信息改为后端下发的短时授权信息。
- 完成登录、主页、加入会议、快速会议、预定会议、会中成员、邀请、聊天、屏幕共享、录制、设置和个人资料流程。
- 为房间、网络、设备、权限和 LiveKit 轨道异常提供明确的用户提示和诊断日志。

## 当前基线

当前项目已经具备:

- 登录页、主页、加入会议页、会中页、预定会议页、共享屏幕页、设置页、资料页和参会者卡片。
- 通过 `MeetingRoom` 连接 LiveKit 房间。
- LiveKit 参会者、轨道、连接和房间事件到 Qt 信号的桥接。
- 本地麦克风和摄像头发布。
- 远端音频播放和远端视频渲染。
- 本地优先的视频宫格。
- 无视频时的头像兜底展示。
- 本地和远端音量检测，以及发言状态高亮。
- 控制台和 `meetex.log` 日志输出。

当前仍未完成:

- 真实登录、身份恢复和用户资料绑定。
- 动态会议号、房间名、参会者名称和 token 获取。
- 快速会议和预定会议创建。
- 屏幕采集和屏幕共享发布。
- 聊天传输、消息模型和聊天界面逻辑。
- 成员列表、邀请面板和基础成员操作。
- 录制控制和录制状态同步。
- 设置页逻辑和本地偏好持久化。

## 功能需求

### 登录与账号

- 登录窗口应通过后端服务认证用户。
- 客户端只保存必要的本地会话信息，例如刷新凭据或用户资料缓存。
- 登录成功后进入主页；未登录关闭登录窗口时退出应用。
- 个人资料页应展示头像、昵称、手机号或邮箱、账号标识。
- 客户端应支持退出登录，并清理本地会话状态。

### 主页

- 主页应提供加入会议、快速会议、预定会议、共享屏幕、设置和个人资料入口。
- 快速会议应向后端申请新会议和 LiveKit token，然后进入会中页。
- 加入会议应打开加入会议流程，并把入会选项传入会议会话。
- 预定会议应打开预定会议表单。
- 从主页发起共享屏幕时，应先创建或加入会议，再发布屏幕共享轨道。

### 加入会议

- 加入会议流程应收集会议号、入会显示名称和入会选项。
- 入会选项包括自动连接音频、入会开启摄像头、入会开启麦克风。
- 客户端应在入会前校验会议号格式。
- 客户端应根据会议号和用户身份向后端请求 LiveKit URL 和短时 token。
- 入会成功后，会议窗口应按用户选择启动本地音视频。
- 入会失败时，应区分会议不存在、无权限、会议过期、网络失败和 token 获取失败。

### 预定会议

- 预定会议页应支持会议主题、开始时间、时长、参会人、会议密码或等候策略。
- 预定操作应通过后端创建会议记录。
- 创建成功后应展示会议号、邀请链接、会议时间和复制/邀请操作。
- 编辑和取消会议依赖后端能力，可在 MVP 后续阶段实现。

### 会中音视频

- 会中页应以响应式宫格展示本地和远端参会者。
- 本地参会者应优先展示。
- 客户端应支持麦克风静音/解除静音、摄像头开启/关闭。
- 按钮状态应反映真实媒体状态，而不是仅根据点击文本切换。
- 客户端应响应远端轨道发布、订阅、静音、解除静音和取消发布事件。
- 参会者没有视频时，应展示头像和名称。
- 本地和远端音量、发言状态应持续更新。
- 断开、重连中、重连成功等房间状态应在 UI 中可见。
- 离开会议时应停止本地采集、远端播放、视频渲染 worker，并断开房间。

### 成员列表

- 成员面板应展示名称、身份、音频状态、视频状态、屏幕共享状态、发言状态和连接质量。
- 成员列表应随参会者加入/离开和轨道变化实时更新。
- MVP 阶段应支持复制参会者身份、定位当前发言者。
- 静音他人、移除参会者、转移主持人等主持人控制需要后端权限支持，作为后续扩展。

### 邀请

- 邀请入口应展示会议号、会议主题、邀请链接和复制按钮。
- 如后端支持通讯录，邀请面板可搜索联系人并发送邀请。
- 没有通讯录后端时，MVP 至少应支持复制邀请文本和会议链接。

### 聊天

- 聊天入口应打开会中聊天面板。
- MVP 阶段支持房间级文本消息。
- 消息应包含发送者身份、显示名、时间戳、正文和发送状态。
- 聊天传输优先使用 LiveKit data message。若需要离线历史或持久化，应由后端单独存储。
- 客户端应处理发送失败、重连后的重发策略和房间不支持聊天能力的情况。

### 屏幕共享

- 屏幕共享入口应允许用户选择显示器或窗口，具体取决于 Windows 和 Qt API 支持情况。
- 开始共享后，应发布一个 LiveKit 屏幕共享视频轨道。
- UI 应展示明确的本地共享状态和停止共享操作。
- 同一客户端同一时间只能有一个本地屏幕共享会话。
- 远端屏幕共享轨道应能和摄像头轨道区分，并可在布局中优先展示。
- 权限拒绝或采集失败时应显示用户可理解的错误信息。

### 录制

- 录制按钮应反映真实录制状态。
- 推荐 MVP 录制方案为后端控制 LiveKit Egress 的服务端录制。
- 客户端向后端请求开始/停止录制，并通过房间 metadata、后端轮询或服务端推送观察录制状态。
- UI 应展示开始中、录制中、停止中、失败和无权限状态。
- 客户端本地录制涉及混音、混流和文件写入，建议作为后续扩展。

### 设置

- 音频设置应列出麦克风和扬声器设备，支持设备选择、麦克风测试和扬声器测试。
- 视频设置应列出摄像头设备，提供预览和默认分辨率/帧率偏好。
- 录制设置应展示默认录制偏好和后端录制存储策略。
- 通用设置应包含语言、开机行为、默认入会选项、日志路径和诊断导出。
- 设置应持久化到本地，并在入会时生效。

### 异常与诊断

- 客户端应为登录失败、token 失败、入会失败、网络中断、设备权限失败、媒体发布失败和轨道订阅失败提供用户提示。
- 详细技术信息应写入日志。
- 日志不得写入完整访问 token 或密钥。
- 诊断导出应包含客户端版本、LiveKit SDK 版本、近期日志、设备名称和会议状态，且不暴露凭据。

## 非功能需求

- 目标平台为 Windows 桌面端。
- UI 框架为 Qt Widgets。
- 语言标准为 C++17。
- 媒体采集、播放和渲染 worker 运行时，会议 UI 应保持响应。
- 离开会议时媒体 worker 应可确定地停止。
- 优先支持双人和小型多人会议。
- 模块设计应支持未来扩展主持人控制、云录制和企业通讯录。

## 验收标准

- 用户可以登录、创建或加入真实会议，并看到一致的房间状态。
- 用户可以选择入会时是否开启麦克风和摄像头。
- 本地和远端音视频状态与 LiveKit 轨道状态保持同步。
- 成员、邀请、聊天、屏幕共享、录制和设置具备 MVP 完整体验。
- 离开或关闭会议会释放 LiveKit 房间资源和媒体 worker。
- 产品构建不再编译固定 LiveKit token。
